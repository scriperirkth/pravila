# Правила обмена 1С

Репозиторий хранит исходные правила обмена и читаемые представления
для анализа, отладки и подготовки изменений через GitHub Connector.

Конфигурации, версии, направления и имена файлов могут меняться.
Механизм и направление устанавливаются по содержимому выбранных правил,
а не по названию файла.

## Текущий состав

- `ПравилаОбменаДанными.xml` — исходный файл правил.
- `readable_20kb/` — байтовые части правил.
- `readable_20kb/index.md` — индекс частей и сведения об исходнике.
- `split_xml.py` — скрипт разбиения.
- `Как делить.txt` — пример ранее использованной команды.
- `UPDATE_GUIDE.md` — порядок обновления.
- `EXCHANGE_PROMPT.md` — шаблон задачи для ИИ.

При замене исходников обновляйте этот список и карту комплектов.

## С чего начать

1. Установить, какой комплект относится к задаче.
2. Прочитать `readable_20kb/index.md`.
3. Проверить соответствие частей выбранному исходнику.
4. По содержимому установить источник, приёмник, механизм и версии.
5. Найти нужное правило и прочитать его существенные зависимости.
6. Получить полный текст изменяемого обработчика.

Не считать правила из репозитория автоматически теми правилами,
которые фактически используются в информационной базе.

## Карта комплектов

| Исходник | Читаемое представление | Подтверждение |
|---|---|---|
| `ПравилаОбменаДанными.xml` | `readable_20kb/index.md` | Направление и версии устанавливать по содержимому; соответствие исходника и частей проверять |

Если комплектов несколько, хранить их раздельно и добавить отдельные
строки с направлением, версиями, SHA-256 и индексом.

## Актуальность представлений

В предыдущей проверке размер корневого XML в листинге отличался
от размера исходника, указанного в индексе частей.
Причина и эквивалентность содержимого этим не установлены.

Пока соответствие не проверено, не смешивать фрагменты корневого XML
и читаемых частей как заведомо одну версию.

Одинаковые имена и расположение в одном репозитории
не доказывают совпадение содержимого.

## Чтение байтовых частей

Часть не является самостоятельным XML-документом или полным правилом.
Граница может проходить внутри тега, XML-сущности, строки и обработчика.

При необходимости читать соседние части в порядке номеров,
без вставки дополнительных символов на границе.

Обработчик считается полностью полученным после чтения его начала
и конца. Поисковый фрагмент или обрезанный ответ не равны полному тексту.

## Связанные источники

- ЗУП: `scriperirkth/zup-structure`.
- Метаданные другой конфигурации: `scriperirkth/structure_met`.

Актуальный маршрут структуры брать из README репозитория structure_met.
После публикации исправленной навигации её ожидаемый вход:
`object_readable_sharded/index.md`.

Не считать этот маршрут опубликованным без проверки.
Не искать структуру УПП внутри pravila.

Метаданные подтверждают структуру и типы.
Правила подтверждают сопоставления и текст обработчиков.
Одно не заменяет другое.

## Обновление

См. [UPDATE_GUIDE.md](UPDATE_GUIDE.md).

Новый комплект частей создавать отдельно, не смешивая со старым.
После обновления сверять контрольную сумму и проверять чтение
одного полного правила через GitHub Connector.

Генератор объектной навигации структуры не считать автоматически
генератором навигации правил.

## Работа с ИИ

См. [EXCHANGE_PROMPT.md](EXCHANGE_PROMPT.md).

Заполнить начало шаблона и передать материалы задачи.
При продолжении не пересылать весь промпт повторно.

Согласованный состав доработки сохранять.
Частичный XML не называть полными правилами.

запись в базы, проведение, удаление или обход прав.

Изменения GitHub выполняются только после отдельного подтверждения.
Секреты и персональные данные не публиковать.
